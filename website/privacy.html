2. Overview

This website and ProcessLama are built to collect as little as possible. Devmil Solutions does not run analytics, advertising or tracking. The website sets no cookies and loads nothing from third-party servers: its fonts, images and scripts come from this site. ProcessLama does not send your process data to Devmil Solutions or to anyone else.

3. Hosting

The website is hosted by GitHub Pages (GitHub, Inc., 88 Colin P. Kelly Jr. Street, San Francisco, CA 94107, USA). When the site is visited, GitHub processes technical access data to deliver it and keep it secure: IP address, date and time, requested page, referrer, browser and operating system. Legal basis: Art. 6(1)(f) GDPR (legitimate interest in a secure and reliable website).

GitHub may process data in the USA. GitHub, Inc. is certified under the EU-U.S. Data Privacy Framework (adequacy decision, Art. 45 GDPR). Details: GitHub privacy statement. Devmil Solutions has no access to these logs.

4. Downloads and release data

The download files are published on GitHub Releases. When you click a download link, your browser fetches the file from github.com, which forwards the request to a GitHub download server such as objects.githubusercontent.com or release-assets.githubusercontent.com. GitHub processes the same technical access data as described under Hosting, on the same legal basis. The list of releases, checksums and release notes is served from this website.

5. Local storage in your browser

The website stores one value in your browser's local storage: the language you chose (preferred-language, en or de). This value stays on your device, is never transmitted, and can be deleted in your browser at any time. Legal basis: § 25(2) no. 2 TDDDG (strictly necessary for a service you requested).

6. The app

Process data stays on your computer

ProcessLama reads information about the processes on your computer from the operating system: names, process and user IDs, user names, executable paths, command lines, and CPU, memory, GPU, network and storage figures. When you open the inspector, it also reads the selected process's open files, sockets (including local and remote addresses), threads and code-signing or security details. This data is processed only on your computer. The app has no accounts, no analytics, no crash reporting and no telemetry, and it never sends process data over the network.

What the app saves

  • Settings, such as the polling interval, columns, appearance, language, release channel and saved filters, in the app's preferences on your computer.
  • Snapshots you take or open, in the app's data folder. A snapshot contains the full process list, including user names, paths and command lines. Exporting writes a copy to the place you choose.
  • A log file with warnings and errors, in the app's data folder, and cached process icons in the temporary folder.

The app stores no passwords or other credentials. You can delete these files at any time, for example by removing the app's data folder.

Update checks

Checking for updates is the only time ProcessLama connects to the internet on its own behalf.

  • macOS: ProcessLama uses the Sparkle update framework. It reads the update feed at https://devmil.de/processlama/download/appcast.xml when you choose “Check for updates” and, if you allow automatic checks when Sparkle asks, about once a day. Sparkle sends a normal web request with its user agent, which names the app, its version and the Sparkle version. It does not send a system profile. The release notes are loaded from this website. The update file is downloaded from GitHub Releases (see section 4) only when you install an update.
  • Linux and Windows: the app checks only when you choose “Check for updates”. It then loads https://devmil.de/processlama/_data/releases.json over HTTPS and compares the builds on your computer. If a newer build exists, “Open downloads” opens the downloads page in your browser. The app does not download or install anything itself.

These requests go to this website, which GitHub hosts. GitHub processes the technical access data described in section 3, including your IP address. Legal basis: Art. 6(1)(f) GDPR (legitimate interest in offering secure updates).

Permissions

  • macOS: ProcessLama asks for no special permissions such as camera, microphone, screen recording or accessibility. It reads what macOS makes available to your user account; where macOS denies access, the inspector says so. For network figures it runs the system tool nettop.
  • Linux: per-process network figures need the processlama-network system service, which runs with administrator (root) rights. The RPM and DEB packages install and start it. In the portable builds, the app offers to install it and asks for your administrator password through polkit. The service counts the bytes each process sends and receives. It does not read packet contents, addresses or ports. It writes these counters to /run/processlama/network.json, which other users on the same computer can read. You can stop it with systemctl disable --now processlama-network.service.
  • Windows: the app runs with your normal user rights. The installer asks for administrator rights to install into Program Files. No service is installed.

Process actions such as terminating or suspending a process only happen when you choose them; ProcessLama asks before it sends a destructive signal.
