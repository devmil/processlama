2. Überblick

Diese Website und ProcessLama sind so gebaut, dass sie so wenig Daten wie möglich erheben. Devmil Solutions setzt keine Analyse-, Werbe- oder Tracking-Dienste ein. Die Website setzt keine Cookies und lädt nichts von Servern Dritter: Schriften, Bilder und Skripte stammen von dieser Website. ProcessLama sendet Ihre Prozessdaten weder an Devmil Solutions noch an Dritte.

4. Downloads und Release-Daten

Die Download-Dateien werden über GitHub Releases veröffentlicht. Wenn Sie auf einen Download-Link klicken, lädt Ihr Browser die Datei von github.com; GitHub leitet die Anfrage an einen eigenen Download-Server weiter, zum Beispiel objects.githubusercontent.com oder release-assets.githubusercontent.com. GitHub verarbeitet dabei dieselben technischen Zugriffsdaten wie unter „Hosting“ beschrieben, auf derselben Rechtsgrundlage. Die Liste der Releases, die Prüfsummen und die Versionshinweise liefert diese Website aus.

5. Lokaler Speicher in Ihrem Browser

Die Website speichert einen einzigen Wert im lokalen Speicher (Local Storage) Ihres Browsers: die gewählte Sprache (preferred-language, en oder de). Dieser Wert bleibt auf Ihrem Gerät, wird nie übertragen und kann jederzeit in Ihrem Browser gelöscht werden. Rechtsgrundlage ist § 25 Abs. 2 Nr. 2 TDDDG (unbedingt erforderlich für einen von Ihnen gewünschten Dienst).

6. Die App

Prozessdaten bleiben auf Ihrem Computer

ProcessLama liest Informationen über die Prozesse auf Ihrem Computer aus dem Betriebssystem: Namen, Prozess- und Benutzer-IDs, Benutzernamen, Programmpfade, Befehlszeilen sowie Werte zu CPU, Arbeitsspeicher, GPU, Netzwerk und Speicher. Wenn Sie den Inspektor öffnen, liest die App zusätzlich die offenen Dateien, Sockets (einschließlich lokaler und entfernter Adressen), Threads sowie Signatur- und Sicherheitsangaben des ausgewählten Prozesses. Diese Daten werden ausschließlich auf Ihrem Computer verarbeitet. Die App hat keine Konten, keine Analyse, keine Absturzberichte und keine Telemetrie, und sie sendet nie Prozessdaten über das Netzwerk.

Was die App speichert

  • Einstellungen wie Abfrageintervall, Spalten, Darstellung, Sprache, Release-Kanal und gespeicherte Filter, in den Einstellungen der App auf Ihrem Computer.
  • Schnappschüsse, die Sie aufnehmen oder öffnen, im Datenordner der App. Ein Schnappschuss enthält die vollständige Prozessliste einschließlich Benutzernamen, Pfaden und Befehlszeilen. Beim Exportieren wird eine Kopie an dem Ort gespeichert, den Sie wählen.
  • Eine Protokolldatei mit Warnungen und Fehlern im Datenordner der App sowie zwischengespeicherte Prozess-Symbole im temporären Ordner.

Die App speichert keine Passwörter oder sonstigen Zugangsdaten. Sie können diese Dateien jederzeit löschen, zum Beispiel indem Sie den Datenordner der App entfernen.

Suche nach Updates

Die Suche nach Updates ist der einzige Anlass, bei dem ProcessLama von sich aus eine Verbindung ins Internet aufbaut.

  • macOS: ProcessLama verwendet das Update-Framework Sparkle. Es lädt den Update-Feed unter https://devmil.de/processlama/download/appcast.xml, wenn Sie „Nach Updates suchen“ wählen, und etwa einmal täglich, wenn Sie automatische Prüfungen erlauben, sobald Sparkle danach fragt. Sparkle sendet eine gewöhnliche Web-Anfrage mit seinem User-Agent, der die App, ihre Version und die Sparkle-Version nennt. Ein Systemprofil wird nicht übertragen. Die Versionshinweise werden von dieser Website geladen. Die Update-Datei wird nur dann von GitHub Releases geladen (siehe Abschnitt 4), wenn Sie ein Update installieren.
  • Linux und Windows: Die App prüft nur, wenn Sie „Nach Updates suchen“ wählen. Sie lädt dann https://devmil.de/processlama/_data/releases.json über HTTPS und vergleicht die Builds auf Ihrem Computer. Gibt es einen neueren Build, öffnet „Downloads öffnen“ die Downloadseite in Ihrem Browser. Die App lädt oder installiert selbst nichts.

Diese Anfragen gehen an diese Website, die von GitHub gehostet wird. GitHub verarbeitet dabei die in Abschnitt 3 beschriebenen technischen Zugriffsdaten, einschließlich Ihrer IP-Adresse. Rechtsgrundlage ist Art. 6 Abs. 1 lit. f DSGVO (berechtigtes Interesse an sicheren Updates).

Berechtigungen

  • macOS: ProcessLama fragt nach keinen besonderen Berechtigungen wie Kamera, Mikrofon, Bildschirmaufnahme oder Bedienungshilfen. Die App liest, was macOS Ihrem Benutzerkonto zugänglich macht; wo macOS den Zugriff verweigert, zeigt der Inspektor das an. Für die Netzwerkwerte startet sie das Systemwerkzeug nettop.
  • Linux: Für Netzwerkwerte pro Prozess ist der Systemdienst processlama-network nötig, der mit Administratorrechten (root) läuft. Die RPM- und DEB-Pakete installieren und starten ihn. In den portablen Builds bietet die App die Installation an und fragt über polkit nach Ihrem Administratorpasswort. Der Dienst zählt die Bytes, die jeder Prozess sendet und empfängt. Paketinhalte, Adressen oder Ports liest er nicht. Er schreibt diese Zähler nach /run/processlama/network.json; andere Benutzer desselben Computers können diese Datei lesen. Sie können den Dienst mit systemctl disable --now processlama-network.service beenden.
  • Windows: Die App läuft mit Ihren normalen Benutzerrechten. Das Installationsprogramm fragt nach Administratorrechten, um in den Ordner „Programme“ zu installieren. Ein Dienst wird nicht installiert.

Prozessaktionen wie das Beenden oder Anhalten eines Prozesses geschehen nur, wenn Sie sie auswählen; vor einem destruktiven Signal fragt ProcessLama nach.
